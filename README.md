# 牌理研习室 · Riichi Mahjong Advisor

一个面向《雀魂》玩家的日本立直麻将牌理分析网页。手动录入当前手牌和局况后，工具会在浏览器本地计算向听数、有效牌、和牌张、可成立役种，并按牌效与安全度给出切牌排序。

> 本项目是学习与复盘工具，不隶属于《雀魂》、Cat Food Studio 或 Yostar。建议只在对局后复盘或规则允许的环境中使用。

## 功能

- 标准四面子一雀头、七对子、国士无双三路线向听计算
- 听牌时枚举和牌张，并扣除手牌、副露、宝牌指示牌和四家牌河中的可见枚数
- 识别断幺九、役牌、平和候选、七对子、国士无双、三色同顺、一气通贯、对对和、混一色/清一色等主要役种
- 14 张状态逐张模拟切牌，比较切后向听与有效牌
- 自家牌河只参与可见牌统计；三家对手牌河与立直状态用于识别现物、筋和字牌可见张数
- 进攻、均衡、防守三种建议权重
- 点击牌面和紧凑牌谱记法两种输入方式，适配手机屏幕
- 本机截图识别，支持文件选择、拖拽、剪贴板粘贴和导入前人工校对
- 自动识别宝牌指示牌和自风，归一化牌河中的横置立直牌，并填写三家对手的立直状态
- 34 种标准日麻牌图片，采用社区维护的公有领域牌图资源
- 手动牌理分析零前端运行时依赖；截图识别通过本地 Python 服务完成

## 快速开始

完整功能需要 Node.js 20+、Python 3.9 和项目根目录下的 `.venv`。首次使用先安装识别依赖：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r backend/requirements.txt
```

以后在项目根目录使用一个命令同时启动网页和本地识别服务：

```bash
npm run dev
```

命令显示“服务已准备完成”后，再打开它打印的 <http://127.0.0.1:4173>。按 `Ctrl+C` 会同时停止两个服务。只使用手动录入、不需要截图识别时，可运行 `npm run serve` 单独启动静态网页。如果之前分别启动过两个服务，请先停止旧进程，避免 4173 或 8765 端口占用。

不要直接双击 `index.html`；页面必须通过上述本地网址打开。开发网页使用禁用缓存的本地服务，修改代码后普通刷新即可获取最新脚本。如果页面提示识别服务未连接，可点击状态按钮重试，或访问 <http://127.0.0.1:8765/api/health> 检查模型状态。

麻将牌素材位于 `public/assets/tiles/`：网页直接使用 34 张带透明背景的低分辨率 PNG。牌胚与标准万、筒、索、字牌图案来自 [FluffyStuff/riichi-mahjong-tiles](https://github.com/FluffyStuff/riichi-mahjong-tiles)，原作者已将全部素材置于公有领域；本项目仅进行图层合成、文件命名与尺寸压缩。完整来源记录见 [`THIRD_PARTY_NOTICES.md`](./THIRD_PARTY_NOTICES.md)。

## 输入规则

牌谱使用常见紧凑记法：

- `m`：万子，`p`：筒子，`s`：索子，`z`：字牌
- `123m456p789s12344z`
- 字牌 `1z` 到 `7z` 依次为东、南、西、北、白、发、中
- `0m`、`0p`、`0s` 会按对应花色的五处理
- 副露用空格分组，例如 `123m 777z`

无副露时，13 张表示等待摸牌状态，14 张表示轮到切牌。有一组副露时分别录入 10/11 张暗手，两组副露时录入 7/8 张，以此类推。

四家牌河都会扣减有效牌的剩余枚数。自家牌河不会被当作对手现物；只有勾选立直的对手牌河会进入现物、筋和危险度计算。截图中检测到横置立直牌时，系统会先转正牌面再分类，并在导入时自动勾选相应对手的立直状态；该结果仍可在分析前手动修改。赤五导入后会保留“赤”标记，牌数规则中仍按对应花色的五计算。

## 建议模型

每个可切牌都会经过以下步骤：

1. 移除该牌，重新计算最低向听数。
2. 枚举所有能降低向听数的下一张牌，并统计剩余枚数。
3. 计算宝牌损失。
4. 对已立直的对手检查现物、筋与字牌可见枚数，得到启发式危险指数。
5. 根据进攻/均衡/防守模式加权排序。

危险指数不是完整牌谱 AI，也不代表绝对放铳率。巡目、对手手出/摸切、立直宣言牌、壁与场况点差等信息尚未完整建模，因此防守判断应作为复盘提示，而不是确定结论。

## 测试

一条命令执行前端测试、后端测试和前后端语法检查：

```bash
npm run check
```

只运行浏览器端纯逻辑测试可使用 `npm test`；只运行识别后端测试可使用 `npm run test:backend`。

## 本地处理与隐私

- 网页只把截图发送到 `127.0.0.1:8765` 的本地识别服务，不会调用云端识图接口。
- HTTP API 在内存中解码和识别图片，默认不会保存上传的截图或牌面切片。
- 只有主动使用离线 CLI 的 `--output`、`--debug-dir` 或数据收集命令时才会写入识别产物。
- `img/`、`backend/debug/`、`backend/output/`、`datasets/private/`、运行日志和本地环境文件均已由 `.gitignore` 排除。
- 提交代码前仍应检查 `git status`，不要主动强制添加私人截图。

## 技术结构

```text
index.html          页面结构
src/app.js          交互与结果展示
src/mahjong.js      纯函数牌理引擎
src/recognition.js  截图 API、识别草稿与校对数据处理
src/styles.css      响应式视觉样式
backend/            本地截图识别核心与 HTTP API
scripts/            一键启动与仓库检查脚本
tests/              Node.js 单元测试
```

截图识别后端提供离线命令行和仅监听本机的 HTTP API，环境和用法见
[`backend/README.md`](./backend/README.md)。网页支持截图选择、拖拽、粘贴、识别框预览和导入前人工校对；确认后才会替换当前手牌与四家牌河。
