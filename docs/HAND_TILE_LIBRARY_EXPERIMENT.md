# 正面手牌模板库实验

> 分支：`experiment/hand-tile-library`
>
> 状态：`1.5.0-alpha.3` 阶段验收通过，已通过默认关闭的配置开关接入正式手牌识别
>
> 范围：只处理自家正面、无旋转、无透视变形的暗手
>
> 最后更新：2026-08-25

## 1. 实验目标

利用雀魂自家手牌切割稳定、牌面图案固定的特点，建立只包含人工确认样本的本地模板库。实验验证模板近邻匹配能否在受控的正面手牌范围内，比旧 TileNet 分类器获得更稳定且可解释的结果。

本实验不处理：

- 四家牌河
- 横置立直牌
- 吃、碰、杠等副露
- 亮光、动画或大面积遮挡牌面
- 牌桌透视四边形修正

`03_table_quad.png` 的误差不会影响本实验，因为 `HandTileExtractor` 直接从原始截图底部切割手牌，不经过牌桌透视校正。

## 2. 为什么不是逐像素完全相等

同一种牌在同一张截图内也会受到切割宽度、缩放插值、亮度、抗锯齿和 JPEG 压缩影响。`323.jpeg` 中两张七筒和两张东风在统一缩放到 `64×64` 后，均有超过3500个像素不完全相等。因此模板库采用相似度距离，而不是文件哈希或逐像素相等判断。

匹配流程：

```text
原始截图底部
    ↓
HandTileExtractor 精准切割
    ↓
去除顶部绿色牌背
    ↓
64×64、白平衡和亮度归一化
    ↓
前景加权颜色距离 + 赤色面积差
    ↓
最近模板类别与第二类别间距校验
    ↓
输出类别，或在距离过大/间距过小时拒绝判断
```

## 3. 私有数据目录

默认目录：

```text
datasets/private/hand_templates/
├── 1m/
├── 2m/
├── ...
├── 0m/
├── 0p/
├── 0s/
└── manifests/
```

该目录已由 `.gitignore` 排除。模板来自私人截图，不得使用 `git add -f` 强制提交。

独立识别一张截图：

```bash
python -m backend.hand_library match /absolute/path/to/screenshot.jpeg
```

复测已经进入模板库的截图时，应排除来自同一截图的模板：

```bash
python -m backend.hand_library match \
  /absolute/path/to/323.jpeg \
  --leave-source-out
```

## 4. 收集人工确认模板

必须先逐张查看截图或审阅切片，再按从左到右的顺序提供标签。禁止直接把未核对的 CNN 输出批量当作标准答案。

```bash
python -m backend.hand_library collect \
  /absolute/path/to/screenshot.jpeg \
  --labels 1m,3m,7m,3p,4p,6p,7p,7p,1z,1z,2z,6z,7z,8p
```

收集命令会：

1. 调用现有 `HandTileExtractor` 切割手牌。
2. 检查标签数与切片数完全一致。
3. 校验标签属于37类支持范围。
4. 按类别保存原始切片。
5. 保存来源、序号、坐标和明暗状态清单。
6. 拒绝覆盖已有的同名模板。

## 5. 覆盖率与留出评估

查看37类覆盖情况：

```bash
npm run hand:coverage
```

执行评估：

```bash
npm run hand:evaluate
```

评估不是把某张切片与它自己比较。测试一个样本时，会排除来自同一张截图的全部模板，只允许使用其他截图中的模板。如果某个类别仅有一个截图来源，该类别会被列入 `skippedWithoutAnotherSource`，不会计入准确率。

## 6. 当前本地基线

已人工审阅 `322.jpeg`～`351.jpeg` 的正面手牌切片。`322～339` 与 `346～351` 已进入模板库，`340～345` 保持为未入库的长期留出集：

- 模板数量：310张
- 类别覆盖：37/37
- 可执行来源隔离评估：310张
- 正确：310张
- 错误：0张
- 拒绝：0张
- 单来源类别：无；赤五索已有3张、来自3个独立截图
- 首次识别完全未入库的 `340～351`：156/156张正确
- 保留未入库的 `340～345`：78/78张正确
- `341` 的最右摸入牌被抬高放大；主流高度切割与白色牌面归一化后13张全部正确
- 启用模板库的本地 HTTP API 健康检查报告310张、37类；上传 `340` 后13张均由 `hand-template-library` 输出，其中旧 CNN 原判 `4p` 的牌被正确匹配为 `5p`

该结果证明当前受控样本适合模板匹配，但不代表所有未来截图必然100%正确。必须继续使用未进入模板库的新截图验证。

## 8. 正式链路开关

模板库默认关闭，不会改变普通启动行为。启用本机 API：

```bash
export MAHJONG_HAND_TEMPLATE_LIBRARY_ENABLED=true
export MAHJONG_HAND_TEMPLATE_LIBRARY_DIR=/Users/mac/code/mahjong-soul-advisor/datasets/private/hand_templates
npm run dev
```

启用后的规则：

1. 只对 `HandTileExtractor` 产生的自家手牌使用模板匹配。
2. 距离不超过 `0.18` 且最近类别领先第二类别至少 `0.02` 时接受。
3. 不满足条件时自动使用原 TileNet 结果。
4. JSON 的 `recognition.source` 为 `hand-template-library` 时，同时保留 CNN 原判、模板距离、类别间距和模板来源。
5. `/api/health` 返回模板库是否启用、样本数和类别数。

关闭开关后，识别服务完全沿用旧 CNN 流程。
